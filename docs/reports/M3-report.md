## 8. 风险和下一步

- **ES 的行为只有真实执行才能发现**：水位动作在录制时踩了两次坑（只设高水位被拒绝；决定新分片能否分配的是低水位），单元测试都测不出来。其他动作也可能有类似的问题，只是还没在更复杂的集群上执行过。
- **"临时"修复不会自动撤销**：提高的水位、分片上限一直留在集群里，验收时是手动恢复的。谁、什么时候撤销临时修复，需要一个机制（M4 周报里"需要你决定的事"的候选）。
- **场景太简单的问题还在**：和 M2 结论一样。M3 证明的是"安全地动手"，不是"诊断更准"。
- **审计表权限**：M4 上云前要把应用账号限制为只能 INSERT。

## 术语表

| 术语 | 白话解释 |
|---|---|
| ActionProposal | 模型唯一能输出的修复内容：选哪个动作、填什么参数、依据哪个假设 |
| 方案哈希（plan_hash） | 方案的指纹。审批批的是这个指纹，方案改一个字都要重新审批 |
| 不安全提议 | 模型提议了白名单以外的动作、参数通不过校验，或者输出不合法 |
| 幂等键 | 同一个方案只能执行一次的标记：恢复、重试时不会重复执行 |
| TOCTOU | "检查时满足、执行时已不满足"：所以执行器执行前要再检查一次 |
| interrupt | LangGraph 让图暂停、等人的方式 |
| post 阶段 | 录制里"执行修复之后"集群的状态，回放评测用它来验证修复 |
| 紧急停止（freeze） | 一个开关：打开后执行器拒绝一切动作，但诊断照常 |
| 哈希链 / 锚定 | 每条审计记录都包含上一条的哈希，改动中间的记录会被发现；锚定是把最新的哈希另存到库外，防整条链被重算 |
| 上线门槛 | 版本能不能上线的底线检查：不安全提议为 0、输出符合契约、录制覆盖够 |
