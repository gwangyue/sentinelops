# ADR-009 根据技术验证修改 03 篇契约（不新增字段）

- 状态：已接受（2026-11-10）
- 相关：03 篇 §3.1、§5.2、§6.1、来源说明；06 篇 §5.3；spike-results.md S1–S4

## 背景

技术验证（spike-results.md）推翻了 03 篇里的几处示例和标注。03 篇是契约，修改要先确认并记录。本次所有改动都只改注释、示例值和来源说明，**没有新增、删除或重命名任何字段**，现有模型不受影响。

## 决策

| 位置 | 改动 | 依据 |
|---|---|---|
| §3.1 `supports` | 去掉【待验证】，写上实测版本 ECK 3.5.0 / ES 9.5.3 | S1 |
| §5.2 `models` | 注释写明参数必须包含 `thinking_budget`；内容从配置文件读取，代码里不写型号 | S3：思考 token 计入 `max_output_tokens`；ADR-008 |
| §6.1 示例 `fault` | 磁盘脚本在 kind 节点上执行，目标 93%；节点名改为 ECK 实际的 `es-target-es-data-N` | S2：在 ES 容器里写盘会被 OOMKill |
| §6.1 示例 `distractors` | `stress_cpu.yaml` 换成对另一个节点的短暂网络延迟 `net_delay.yaml` | S2：kind 上 CPU 指标是整个 VM 的，CPU 压力无法定位到单个节点 |
| §6.1 示例 `symptom_wait.timeout_s` | 300 → 120 | S2：5 种故障都在 60 秒内出现症状 |
| §6.1 真实答案标签 | 节点宕机和网络分区统一为 `es.node_unavailable` | 从只读 API 看两者的症状相同，见 06 篇 §5.3 |
| 来源说明第 2 条 | “未核实”改为 S4 的实测结论 | S4 |

## 放弃的方案

| 方案 | 放弃原因 |
|---|---|
| 给 `VersionComponents` 加一个独立的 `thinking_budget` 字段 | 它只是模型参数之一，放进 `models` 的 dict 就够了，不值得改契约结构 |
| 保留 `es.node_down` 和 `es.network_partition` 两个标签 | Agent 只有只读 API，分不清两者；硬分会让评分惩罚一个本来无法做出的区分 |

## 后果

- 网络延迟作为干扰项**还没有实测**（S2 只验证了网络分区）。M2 D8 做干扰项变体时先验证：延迟期间集群保持 green，并且不会触发主故障的检测器。不满足就换其他干扰项。
- 以后如果加入能区分两者的数据来源（例如 K8s 事件），可以把 `es.node_unavailable` 拆开，届时再写一条 ADR。
