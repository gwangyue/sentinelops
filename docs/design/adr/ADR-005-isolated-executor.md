# ADR-005 执行器是独立进程，单独持有写凭证

- 状态：已接受（2026-11-09）
- 相关：01 篇 §1、§5.1、§6，03 篇 §4.4，07 篇 §3

## 背景

修复动作需要写权限。提示词注入无法根除，所以必须保证：即使调查引擎被完全操纵，它也做不出白名单以外的写操作。

## 决策

- 执行器单独一个进程、单独一个 K8s 命名空间、单独一份凭证，并且没有外网出口。
- 执行器只接收 `(plan_id, approval_id, idempotency_key)`，自己从 Postgres 读取方案和审批记录、重新计算方案哈希、重新执行前置检查，然后才执行。
- 执行器不依赖 `core`。

## 放弃的方案

| 方案 | 放弃原因 |
|---|---|
| 在调查图的节点里直接执行 | 写凭证会出现在 LLM 所在的进程里 |
| 依靠提示词约束 Agent 不做危险操作 | 换一种说法就能绕过 |

## 后果

- 好处：写权限有清晰的上限；单独审计执行器的代码就能证明安全性。
- 代价：多一个进程和一份部署配置；回放模式下需要一个执行器的模拟实现。
