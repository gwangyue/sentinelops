# ADR-008 诊断用 Gemini Flash 档，评审用 Pro 档；所有调用经过统一封装

- 状态：已接受，具体型号在技术验证 S3 中确定（2026-11-09）
- 相关：01 篇 §3.4、06 篇 §6.1

## 背景

- 诊断调用频繁（每次调查都有多轮工具调用，评测时还要乘以用例数和重复次数），对成本敏感。
- 评审模型用于失败归类。如果用同一个模型给自己的输出打分，分数会偏高。

## 决策

- 诊断：Flash 档。
- 评审：Pro 档，只用于失败归类的语义标签，不参与上线决策。
- 所有模型调用都经过 `core/llm` 封装：按用途路由、执行预算、打上版本标签、统一计费；在企业环境下可以改为走企业 AI 网关。
- 模型及其参数计入 AgentVersion。

## 放弃的方案

| 方案 | 放弃原因 |
|---|---|
| 诊断和评审都用同一个模型 | 自我评价偏高 |
| 诊断也用 Pro 档 | 成本高；而且项目要证明的是"上下文和记忆"带来的提升，而不是"换一个更强的模型"带来的提升 |

## 后果

- 好处：评测成本可控；更换模型本身也可以作为一个对照实验。
- 代价：Flash 档在复杂推理上可能不够。如果"上下文完美"基线（06 篇 §4.5）的分数也很低，就说明是模型能力的问题，再考虑升级为 Pro 档。
