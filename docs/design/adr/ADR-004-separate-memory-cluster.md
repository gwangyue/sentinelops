# ADR-004 Agent 的记忆存放在独立的 ES 集群（es-memory），不和被管集群混用

- 状态：已接受（2026-11-09）
- 相关：01 篇 §3.3、05 篇

## 背景

记忆需要关键词和向量的混合检索，ES 是自然的选择。而被管的 ES 集群（es-target）就在旁边，看起来可以直接复用。

## 决策

记忆、知识库和基线存放在单独的 es-memory 集群（1 个节点），和 es-target 物理隔离。

## 放弃的方案

| 方案 | 放弃原因 |
|---|---|
| 存放在 es-target 的单独索引里 | 往 es-target 注入"磁盘写满"等故障时，Agent 自己的记忆也写不进去了；而且被管系统的管理员可以直接读写 Agent 的记忆，形成一个注入入口 |
| 用 Postgres + pgvector | 可行，但放弃了展示作者在 ES 检索方面的专长（RRF 混合检索、精排） |

## 后果

- 好处：故障隔离；权限边界清楚；可以充分展示检索能力。
- 代价：多运行一个 ES 节点，本地内存占用增加约 1–2 GiB【估算】。
