# ADR-006 用 LangSmith 做观测和数据集管理，统计和归因自己实现

- 状态：已接受（2026-11-09）
- 相关：06 篇 §9

## 背景

需要 Trace、数据集版本、实验对比这些能力。作者明确要求不在观测系统上花时间，但在"数据集的设计和使用"上要做出深度。

## 决策

- LangSmith 负责：Trace、数据集存储和版本标签、split、实验运行（`num_repetitions`）、查看单个用例和实验对比。
- 本项目自己实现：按场景聚类的配对 bootstrap、失败标签和分组、上线门槛、收敛曲线、笨基线。
- 数据集以 git 为唯一真实来源，LangSmith 上的是同步副本。

## 放弃的方案

| 方案 | 放弃原因 |
|---|---|
| 自建观测和评测平台 | 重复造轮子，也不是本项目的亮点 |
| Langfuse 或 Phoenix 自托管 | 可以，但作者已经熟悉 LangSmith，而且学习材料也围绕 LangChain 栈展开 |
| 完全依赖 LangSmith 界面上的统计 | 界面显示的是平均分和标准差，没有按场景聚类的置信区间【推断】 |

## 后果

- 好处：不在基础设施上花时间；深度集中体现在统计和归因上。
- 代价：Trace 和数据会发往 LangSmith 的 SaaS（数据外流，见 07 篇 §6）；依赖 SDK 的接口，需要在技术验证 S4 中确认。
