# ADR-001 外层用 LangGraph 编排固定流程，内层用 Deep Agents 做诊断

- 状态：已接受（2026-11-09）
- 相关：01 篇 §3.2、02 篇 §1

## 背景

调查流程里有两类性质完全不同的工作：

- 审批、执行、验证必须是确定的，可审计、可恢复。
- 诊断是开放式的探索，需要模型自己规划调查步骤、调用工具、启动子 Agent。

## 决策

- 主流程用 LangGraph 的固定节点和边实现。人工介入用 `interrupt()`，状态用 Postgres checkpointer 持久化。
- 诊断作为其中一个节点，内部用 Deep Agents 实现。诊断节点只有只读工具，不开启 `interrupt_on`。

## 放弃的方案

| 方案 | 放弃原因 |
|---|---|
| 整个系统做成一个 Deep Agent | 审批、执行这类必须确定的步骤会交给模型来规划；审计和恢复都变得困难 |
| 整个系统都用 LangGraph 手写，包括诊断 | 诊断需要灵活的规划和子 Agent，手写成本高，也展示不了 Deep Agents 的用法 |

## 后果

- 好处：确定性的部分和探索性的部分边界清楚，各自可以单独评测。
- 代价：需要在技术验证 S3 中确认 Deep Agent 作为节点嵌入时，checkpoint 和 Trace 的行为符合预期。
