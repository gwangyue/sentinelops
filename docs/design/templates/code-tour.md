# 代码导览（模板）

> 每个里程碑结束时，由 Claude Code 按本模板生成，保存为 `docs/reports/<里程碑>-code-tour.md`。
> 目的：让没有亲手写代码的负责人，在 30–40 分钟内建立起对系统的心智模型：一次调查从哪里进来、经过哪些地方、在哪里可能出错。
> 写作规则同验收报告：每一站先用一句人话说明，术语第一次出现时紧跟白话解释。

## 1. 路线图

用一张图（Mermaid 或 ASCII）画出这次导览经过的所有站点，从命令行入口到最终输出。

## 2. 逐站讲解

导览的主线是**一次完整的调查**。M1 走"巡检 → 诊断 → 报告"；M3 之后加上"审批 → 执行 → 验证 → 写入记忆"。

每一站按同样的格式：

| 项 | 内容 |
|---|---|
| 位置 | `文件:行号`，函数或类名 |
| 人话 | 这一步在做什么，一两句话 |
| 输入 / 输出 | 用的是哪个契约（03 篇） |
| 关键概念 | 术语 + 白话解释 |
| 为什么这样设计 | 对应哪一节设计或哪条 ADR |
| 可能出错的地方 | 出错时会表现成什么样，由哪个测试或护栏拦住 |
| 面试可能被问 | 1 个问题 + 简短答案 |

## 3. 先预测，再运行

列出 3 个练习，负责人先写下预测，再运行，最后对照结果。例如：

| # | 要运行的命令 | 请先预测 | 实际结果（运行后填写） |
|---|---|---|---|
| 1 | | 例如：top-1 是哪个根因、大约调几次工具 | |
| 2 | | | |
| 3 | | | |
