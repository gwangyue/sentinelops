# 里程碑验收报告（模板）

> 每个里程碑结束时，由 Claude Code 按本模板生成，保存为 `docs/reports/<里程碑>-report.md`，例如 `docs/reports/M1-report.md`。
> 读者是项目负责人：懂技术，但没有逐行看过代码。目标是 20 分钟读完，就能判断这个里程碑是否符合预期。

## 写作规则

1. **每一节的第一行是一句"人话结论"**：不用任何术语也能看懂。例如："回放功能能用：同一个故障录一次，回放 3 次，结果完全一样。"
2. **保留专业术语，但第一次出现时，紧跟一句白话解释**。例如："按场景聚类的 bootstrap（把同一种故障的几次录制当成一组来重新抽样，避免把彼此相关的结果当作独立样本，导致区间算得过窄）"。
3. **每个结论都要附证据**：命令 + 关键输出（只截取相关的几行，不贴整屏）。没有证据的，写"未验证"。
4. **不夸大**：不用"完美""全面"这类词；"显著"只在统计意义上使用；没做完就直接写没做完。
5. **数字要说明含义**：单次结果、区间，还是估算。
6. **术语表放在文末**：报告里出现过的术语，每个一行白话解释。
